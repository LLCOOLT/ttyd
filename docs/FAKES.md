# Fakes

Policy: C-level fakes are allowed, also when they only bring a function nearer to 100%. A fake is a behaviour-identical C trick (extra temp, no-op cast, dead guard, padding, inline helper, pragma) that makes the compiler emit the target code or layout. No fake uses assembly: there are no asm blocks or asm-backed functions in place of C.

Every fake is marked at its site with a `// FAKE: ...` (or `/* FAKE: ... */`) comment and has a row here, one row per function. Cleanup means replacing a fake with natural C that still matches (all five builds still report their files OK), then deleting its comment and its row.

This list is built from the FAKE comments in src/, rels/ and libs/. It covers all seven versions: the Version column lists the builds where the fake is compiled, as `JP` (G8MJ01), `US` (G8ME01), `PAL` (G8MP01), `DEMO_US` (G8ME01_DEMO), `DEMO_JP` (G8MJ01_DEMO), `DEMO_US2` (G8ME01_DEMO2) and `DEMO_EU` (G8MP01_DEMO) in that order, or `all` for every build that compiles the file (for a file only some builds compile, such as `rels/tst`, which only PAL and the Japanese demo have, or the RELs outside the seven of the September 2004 demos, `all` means those builds). A function with several fakes has one row; the Fake and Natural shape cells number them (1), (2) and say which builds each applies to when that differs. The Fake column summarises the comment text; "see comment" in the last column means the natural shapes tried are in the comment or were not recorded.

Why a no-op cast or a spare temp can change the output: MWCC builds an expression tree for every statement, and the code generator works from that tree, not from the C semantics. A redundant cast such as `((PartyEntry*)party)->moveFrames`, where `party` already has that type, or a value parked in an extra local, is an extra node. Folding it away comes late, so earlier passes still see it. That changes three things. First, scheduling and CSE: a byte-offset access `*(T*)((u8*)p + K)` is an indirect load, a field access is a member load, and the passes treat them differently, so the order of loads or of an address add can move. Second, register colouring: each named local or inline temporary gets its own virtual register and number, and the allocator colours in number order, so the same value through a temp can land in another register. Third, inline cost: with `-inline auto,deferred`, whether a callee is inlined depends on the caller's estimated size, which counts tree nodes; removing a cast can bring a caller under the limit and pull a whole callee in (see npcdrv fbatHitCheck). The no-op cast fakes added in the structs cleanup (party.c, mot_roll.c, ac_stick_rotate.c, npcdrv.c) all replaced raw byte offsets. They keep the original tree shape but name the field, so the struct layout is the single source of truth while the bytes stay identical.
